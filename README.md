# Marketing Tarot

A four-card tarot reading generator for merlinitemarketing.com, built from Kelly's brief
(`Marketing-Tarot-for-Mike (1).pdf`). A visitor picks a marketing question, shuffles,
gets four cards dealt face down, turns each one over, and reads them on the page. A
"Download as PDF" button saves the reading as a PDF, built right in the browser. It is
styled to match the site it lives on: the teal "reading" arch of the Marketing Tarot
landing page, cream text, clay buttons, gold card edges, and the site's fonts (see "Look
and feel").

No dependencies beyond Node 20+ (and Python with Pillow, only to regenerate card images).

## How it's hosted

- **GitHub Pages** serves the `site/` folder: the widget page and the 78 card images,
  live at https://madfable.github.io/marketing-tarot/. `.github/workflows/pages.yml`
  publishes it on every push to `main`.
- **Squarespace** embeds it on the page, either as an iframe (recommended) or by pasting
  the inline build into a Code Block. Both need a Business plan or higher. See "Embed in
  Squarespace" below.

## Layout

```
data/deck.json                 Kelly's copy: 7 spreads, 78 cards, footer. Source of truth.
site/                          The static widget (what GitHub Pages serves)
  index.html                   Standalone page + site config (Services URL, image folder)
  styles.css                   All styles, scoped under .mt-widget, plus print styles
  app.js                       Shuffle, turn-over, PDF button, iframe messaging
  pdf.js                       Builds the PDF in the browser (no libraries)
  deck.js                      GENERATED from data/deck.json (npm run build:deck)
  cards/                       78 web-sized card images, the-fool.jpg ... king-of-pentacles.jpg
assets/cards-src/              Full-size scans (git-ignored, regenerated by npm run cards)
squarespace/iframe-embed.html  Snippet to paste into a Squarespace Code Block (recommended)
dist/squarespace-code-block.html   GENERATED inline alternative (npm run build:embed)
.github/workflows/pages.yml    Deploys site/ to GitHub Pages
scripts/
  build-deck.mjs               data/deck.json -> site/deck.js (validates the JSON)
  build-embed.mjs              -> dist/squarespace-code-block.html
  download-cards.mjs           Fetches the 78 scans from Wikimedia Commons into assets/cards-src/
  resize-cards.py              Makes the 480px web copies in site/cards/ (needs Pillow)
  resize-cards.mjs             Runs resize-cards.py with python3 or python
  dev-server.mjs               Local preview, also serves the test suite
test/                          Browser test suite for the widget (open /test/ on the dev server)
```

## Run it locally

```bash
npm run dev
```

Open http://localhost:8787. `npm test` validates `deck.json` and syntax-checks the scripts.
http://localhost:8787/test/ runs the widget's browser test suite (shuffle, turning cards
over one by one, rendering of all 78 cards, hash restore, escaping, PDF generation, iframe
messaging, accessibility basics)
and shows pass/fail on the page, with a link to open the last generated PDF. The suite also
saves that PDF to `dist/last-reading.pdf`, served at http://localhost:8787/test/last-reading.pdf.
http://localhost:8787/test/embed.html loads the real Squarespace snippet against the dev
server, for checking the iframe height and URL mirroring by hand.

## Deploy to GitHub Pages

Push to `main`. The workflow regenerates `deck.js`, stamps the asset links in `index.html`
with content hashes (`app.js?v=1a2b3c…`, via `scripts/stamp-assets.mjs`) and publishes
`site/`. Pages is already set to the "GitHub Actions" source in the repo settings.

GitHub Pages tells browsers to cache every file for 10 minutes. The hashed links mean a
browser can never pair an old cached script with new styles after a deploy; it either
shows the whole old version (for up to 10 minutes, or until a hard refresh with
Ctrl+Shift+R) or the whole new one.

Updating Kelly's copy later is: replace `data/deck.json`, run `npm run build:deck` (it
validates ids, positions, and meanings), and push.

GitHub Pages doesn't let you set response headers, so there is no frame-ancestors
restriction; any site could iframe the widget. That's acceptable for this content.

## Embed in Squarespace

**Option A, iframe (recommended).** The Marketing Tarot landing page on
merlinitemarketing.com is one big Code Block that Kelly wrote by hand. Near the bottom of
its teal "reading" section is a placeholder: a `<div class="slot">` holding the note
"MIKE: put the tarot generator embed here" and the text "[Mike's tarot generator goes
here]". Edit that Code Block and replace that whole div (opening tag to closing tag) with
the contents of `squarespace/iframe-embed.html`. On any other page, paste the snippet
into a Code Block of its own.

The snippet already points at the GitHub Pages URL. The widget's background is the same
teal as the arch, so the frame is invisible, and because the page already has "Take a
breath and shuffle" above it, the widget leaves out its own title whenever it is inside
an iframe (`showHeader: "auto"` in `app.js`; set it to `true` or `false` to force it).
The widget posts its height to the parent page so the iframe resizes as the reading
appears, and the snippet mirrors the reading into the page URL (`#q=2&c=5,17,40,61`) in
both directions, so a copied or refreshed page brings the same four cards back. Styling
stays isolated from the Squarespace theme.

The snippet answers the widget's first height message with an "ack"; only then does the
widget hide the frame's own scrollbar. If the script never runs (Squarespace 7.0 sites
with "Ajax loading" on only run Code Block scripts on a full page load; 7.1 sites are
fine) the frame stays at its 160px starting height but keeps a scrollbar, so the reading
is still reachable. On a 7.0 site, turn Ajax loading off under Design > Site Styles.

**Option B, inline.** Build the snippet and paste `dist/squarespace-code-block.html`
into a Code Block:

```bash
npm run build:embed
```

Card images still load from GitHub Pages (they're served with permissive CORS, which the
PDF builder needs). The widget's CSS is scoped under `.mt-widget`, but the Squarespace
theme's global styles can still leak in, so check it on the live page.

## Look and feel

The widget copies the landing page's own CSS rather than approximating it. Everything is
a variable at the top of `site/styles.css`:

| Token | Value | Used for |
| --- | --- | --- |
| `--mt-bg` | `#264349` | page background, the same teal as the arch |
| `--mt-bg-deep` | `#1e373c` | card backs |
| `--mt-ink` / `--mt-ink-soft` | `#f4f1eb` / `#d9e2df` | cream text |
| `--mt-sand` | `#e6cfb6` | script accents, position labels, links |
| `--mt-gold` | `#c9a27e` | card edges and the crescent moon |
| `--mt-clay` | `#93603c` | buttons (the site's "Let's talk" colour; white on it passes AA) |
| `--mt-clay-light` | `#a8744f` | card fronts |
| `--mt-field` | `#fbf9f5` | the dropdown |

Fonts are the three families the landing page loads from Google Fonts: Playfair Display
for headings, Inter for text, Caveat for the handwritten accents ("tap to flip", the
face-down hint). The widget is its own document inside the iframe, so `site/index.html`
loads them itself. The card back reuses the moon from Kelly's card illustration.

If Kelly ever changes the arch colour, change `--mt-bg` to match and push. The print
styles swap the variables to dark-on-white, and the PDF has its own copy of the palette
at the top of `site/pdf.js` (teal ink, clay accent).

## How a reading works

- Every question uses the same four-card layout. The position labels come from the
  chosen spread in `deck.json`.
- Four cards are drawn at random from all 78 with no repeats (Fisher-Yates using
  `crypto.getRandomValues`, with rejection sampling so every card is equally likely).
  All upright; reversals are off (`"reversals": false`).
- All four cards are decided the moment the visitor shuffles, then dealt face down. The
  visitor turns them over one at a time, in any order, by tapping or clicking a card (a
  real button, so it works from the keyboard and names the position for screen readers).
  Turning a card only reveals it; the four cards can't change or repeat while flipping.
- Each card shows the position label, image, name, classic meaning, then marketing meaning.
  The "Download as PDF" button appears once all four are face up.
- The reading is stored in the URL hash so a refresh, or a shared link, shows the same
  cards. A restored reading comes back face up, since it has already been seen.
- The footer under every reading comes from `deck.json`, with the last sentence linked
  to Kelly's services page (https://merlinitemarketing.com/marketing-services, set in
  `site/index.html`), opening in a new tab so the reading stays put.

## Download as PDF

`site/pdf.js` writes the PDF itself: US Letter, Helvetica, one block per card with the
card image on the left and the position, name, classic meaning and marketing meaning on
the right, Kelly's footer line with a clickable Services link, and an image credit.
Readings run to one or two pages. Nothing is uploaded anywhere; the file is built in the
visitor's browser and saved as `marketing-tarot-reading.pdf`.

Details worth knowing:

- Text is set in the PDF standard fonts, so no font files are embedded. Curly quotes,
  dashes and accented Latin characters are supported; anything outside Latin-1 (emoji)
  becomes `?`.
- Card images are the site's JPEGs embedded as-is. If an image can't be fetched the PDF
  still builds without it.
- Line wrapping is measured with Arial, which shares Helvetica's metrics, with a small
  safety margin.
- The page also has print styles, so Ctrl+P / "Save as PDF" gives a clean two-column
  layout as a fallback.

## Card images

Kelly's note: use scans of the original 1909 Pamela Colman Smith deck (public domain in
the US), not the US Games 1971 recolored version, and don't call it "Rider-Waite" on the
page. The widget and the PDF call it "the classic 1909 tarot".

The images come from Wikimedia Commons, which holds the full deck as "Pam-A" scans (the
first printing), tagged public domain, artist Pamela Colman Smith, dated 1910. Kelly's
suggested source, sacred-texts.com, refuses scripted downloads, so it's documented in the
script but not used.

```bash
npm run cards
```

That runs two steps: `scripts/download-cards.mjs` fetches the 960px scans into
`assets/cards-src/` (git-ignored, about 45 MB, Commons rate-limits so it takes a few
minutes), then `scripts/resize-cards.py` writes 480px progressive JPEGs into `site/cards/`
(about 9 MB total, these are deployed). The resize step needs Python 3 with Pillow
(`pip install pillow`); `scripts/resize-cards.mjs` finds `python3` or `python` for you.
The repo already contains the finished `site/cards/`, so this only matters if you want to
regenerate them.

Files are named `site/cards/<slug>.jpg` where the slug is the card name lowercased with
dashes (`the-fool.jpg`, `ace-of-wands.jpg`, `king-of-pentacles.jpg`). If a file is missing
the widget shows a named placeholder instead of a broken image.

## Updating the copy

Kelly said she'll send a new JSON when she edits copy. Replace `data/deck.json`, run
`npm run build:deck` (it validates ids, positions, and meanings), and push. The
questions, position labels, card meanings and footer all come from that file. (Her JSON
also carries an `email_box` section; the email feature was dropped, so it's simply
ignored.) Headings, button labels, the "tap to flip" wording, and the PDF messages live at
the top of `site/app.js` and can be overridden from `MARKETING_TAROT_CONFIG` in
`index.html`.
