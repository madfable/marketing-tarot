# Marketing Tarot

A four-card tarot reading generator for merlinitemarketing.com, built from Kelly's brief
(`Marketing-Tarot-for-Mike (1).pdf`). A visitor picks a marketing question, shuffles,
pulls four cards, and reads them on the page. Below the reading there can be an optional
box to email the reading to themselves, with an unchecked newsletter checkbox.

No dependencies beyond Node 20+ (and Python with Pillow, only to regenerate card images).

## How it's hosted

- **GitHub Pages** serves the `site/` folder: the widget page and the 78 card images.
  `.github/workflows/pages.yml` publishes it on every push to `main`.
- **Squarespace** embeds it on the page, either as an iframe (recommended) or by pasting
  the inline build into a Code Block. Both need a Business plan or higher.
- **Email box**: off for now. Sending an email needs a server that holds a mail API key,
  and GitHub Pages can't run one. The Netlify function in `netlify/` is ready whenever an
  email backend is chosen. See "Email box" below.

## Layout

```
data/deck.json                 Kelly's copy: 7 spreads, 78 cards, footer, email box text. Source of truth.
site/                          The static widget (what GitHub Pages serves)
  index.html                   Standalone page + site config (URLs, email endpoint)
  styles.css                   All styles, scoped under .mt-widget
  app.js                       Shuffle, reveal, email form, iframe height
  deck.js                      GENERATED from data/deck.json (npm run build:deck)
  cards/                       78 web-sized card images, the-fool.jpg ... king-of-pentacles.jpg
assets/cards-src/              Full-size scans (git-ignored, regenerated by npm run cards)
squarespace/iframe-embed.html  Snippet to paste into a Squarespace Code Block (recommended)
dist/squarespace-code-block.html   GENERATED inline alternative (npm run build:embed)
.github/workflows/pages.yml    Deploys site/ to GitHub Pages
netlify/functions/send-reading.mjs   Optional: POST /api/send-reading emails the reading
netlify/lib/reading-email.mjs        Builds the email HTML/text from the deck
netlify/lib/deck.mjs                 GENERATED from data/deck.json, used by the function
netlify.toml                   Config for the optional Netlify deployment
scripts/
  build-deck.mjs               data/deck.json -> site/deck.js + netlify/lib/deck.mjs (validates the JSON)
  build-embed.mjs              -> dist/squarespace-code-block.html
  download-cards.mjs           Fetches the 78 scans from Wikimedia Commons into assets/cards-src/
  resize-cards.py              Makes the 480px web copies in site/cards/ (needs Pillow)
  dev-server.mjs               Local preview with the function mounted, dry-run email
  test-send-reading.mjs        Function tests, also writes dist/email-preview.html
```

## Run it locally

```bash
npm run dev
```

Open http://localhost:8787. `npm test` runs the email function tests and writes an
email preview to `dist/email-preview.html`.

## Deploy to GitHub Pages

1. Create a repository on GitHub (public, unless the account has Pages for private repos).
2. Push this folder to its `main` branch. Kelly's brief files and the full-size scans are
   git-ignored; `site/cards/` (about 9 MB) is committed on purpose.
3. In the repo: Settings > Pages > Build and deployment > Source: **GitHub Actions**.
4. The workflow runs on the push and prints the site URL, normally
   `https://madfable.github.io/marketing-tarot/`. Open it to confirm the widget works there.

Updating Kelly's copy later is: replace `data/deck.json`, push. The workflow regenerates
`deck.js`. (`npm run build:deck` does the same locally and validates the file.)

GitHub Pages doesn't let you set response headers, so there is no frame-ancestors
restriction; any site could iframe the widget. That's acceptable for this content.

## Embed in Squarespace

**Option A, iframe (recommended).** Paste `squarespace/iframe-embed.html` into a Code
Block and it already points at the GitHub Pages URL. The widget posts its
height to the parent page so the iframe resizes as the reading appears. Styling stays
isolated from the Squarespace theme.

**Option B, inline.** Build the snippet with the Pages URL and paste
`dist/squarespace-code-block.html` into a Code Block:

```bash
npm run build:embed -- --site=https://madfable.github.io/marketing-tarot
```

Card images still load from GitHub Pages. The widget's CSS is scoped under `.mt-widget`,
but the Squarespace theme's global styles can leak in, so check it on the live page.
Readings restore from the page URL's hash either way.

## Card images

Kelly's note: use scans of the original 1909 Pamela Colman Smith deck (public domain in
the US), not the US Games 1971 recolored version, and don't call it "Rider-Waite" on the
page. The widget and the email call it "the classic 1909 tarot".

The images come from Wikimedia Commons, which holds the full deck as "Pam-A" scans (the
first printing), tagged public domain, artist Pamela Colman Smith, dated 1910. Kelly's
suggested source, sacred-texts.com, refuses scripted downloads, so it's documented in the
script but not used.

```bash
npm run cards
```

That runs two steps: `scripts/download-cards.mjs` fetches the 960px scans into
`assets/cards-src/` (git-ignored, about 45 MB, Commons rate-limits so it takes a few
minutes), then `scripts/resize-cards.py` writes 480px progressive JPEGs into `site/cards/`
(about 9 MB total, these are deployed). The resize step needs Python with Pillow
(`pip install pillow`). The repo already contains the finished `site/cards/`, so this
only matters if you want to regenerate them.

Files are named `site/cards/<slug>.jpg` where the slug is the card name lowercased with
dashes (`the-fool.jpg`, `ace-of-wands.jpg`, `king-of-pentacles.jpg`). If a file is missing
the widget shows a named placeholder instead of a broken image.

## How a reading works

- Every question uses the same four-card layout. The position labels come from the
  chosen spread in `deck.json`.
- Four cards are drawn at random from all 78 with no repeats (Fisher-Yates using
  `crypto.getRandomValues`). All upright; reversals are off (`"reversals": false`).
- Each card shows the position label, image, name, classic meaning, then marketing meaning.
- The reading is stored in the URL hash (`#q=2&c=5,17,40,61`) so a refresh, or a link,
  shows the same cards.
- The footer under every reading comes from `deck.json`, with the last sentence linked
  to the Services page.

## Email box

Currently hidden: `emailEndpoint` is `""` in `site/index.html`. Set it to a URL and the
box appears, posting JSON to that URL:

```json
{ "email": "...", "newsletter": false, "spread": 2, "cards": [0, 22, 45, 77], "website": "" }
```

The server rebuilds the reading from the question index and card ids, so the endpoint
cannot be used to send arbitrary text. `website` is a honeypot. The email includes the
question, the four position labels, the cards with both meanings, the footer with the
Services link, and a view-online link.

**What Squarespace can and can't do here.** Squarespace Email Campaigns can collect
newsletter sign-ups through its own Newsletter Block or Form Block, but it has no API for
adding subscribers from custom code, and it can't send a per-visitor email with custom
content like a reading. So:

- The newsletter opt-in can go to Squarespace by placing a Squarespace Newsletter Block
  under the widget instead of the checkbox. Nothing in this repo needs to change for that.
- Emailing the reading itself always needs a transactional mail service (Resend,
  SendGrid, Postmark, Mailgun) called from a small server.

**The ready-made server: Netlify function.** `netlify/functions/send-reading.mjs` sends
through Resend and optionally subscribes the address through Mailchimp. Deploy this repo
to Netlify as well (it uses `netlify.toml`), set the variables below, then point
`emailEndpoint` at `https://YOUR-NETLIFY-SITE/api/send-reading` and set
`ALLOWED_ORIGINS` to the origin the widget runs on (the GitHub Pages origin, or the
Squarespace site for the inline embed).

| Variable | Purpose |
| --- | --- |
| `RESEND_API_KEY` | Sends the email through [Resend](https://resend.com). Required. |
| `FROM_EMAIL` | e.g. `Kelly at Merlinite Marketing <hello@merlinitemarketing.com>`. The domain must be verified in Resend. |
| `REPLY_TO` | Optional. |
| `SITE_URL` | Where the widget is hosted, used for card image and view-online links. |
| `SERVICES_URL` | Defaults to `https://merlinitemarketing.com/services`. |
| `MAILCHIMP_API_KEY`, `MAILCHIMP_SERVER_PREFIX`, `MAILCHIMP_LIST_ID` | Newsletter opt-in. If unset, the checkbox is accepted but nothing is subscribed. |
| `MAILCHIMP_DOUBLE_OPT_IN` | `1` to send Mailchimp's confirmation email instead of subscribing directly. |
| `ALLOWED_ORIGINS` | Comma-separated origins allowed to call the endpoint. |
| `DRY_RUN` | `1` to log instead of sending (the dev server sets this). |

If Kelly uses a different newsletter tool (Kit, Flodesk), swap the
`subscribeWithMailchimp` function in `send-reading.mjs`. Everything else stays.

## Updating the copy

Kelly said she'll send a new JSON when she edits copy. Replace `data/deck.json`, run
`npm run build:deck` (it validates ids, positions, and meanings), and push. The email
box text, footer, questions, and card meanings all come from that file. Headings, button
labels, and the error messages live at the top of `site/app.js` and can be overridden
from `MARKETING_TAROT_CONFIG` in `index.html`.
